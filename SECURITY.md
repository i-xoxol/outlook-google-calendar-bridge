# Security reporting

Do not put credentials, real events, meeting links, account exports, or private
deployment information in a public issue. If private vulnerability reporting is
available, use the repository's **Security → Report a vulnerability** route.
Otherwise contact the maintainer through the public GitHub profile to arrange a
private report before sharing sensitive details.

Include affected version, fictional reproducer, likely impact, and suggested
mitigation. Supported fixes target the latest public release. Provider account
compromise, revoked authorization, and tenant policy require action with the
relevant provider or administrator.
